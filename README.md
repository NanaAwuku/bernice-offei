# berniceoffei.com — memorial website

Memorial site for Bernice Ofeibea Offei (25 February 1963 – 12 September 2026), built with
Next.js (App Router). The design and content were ported from the approved Astro build
(`berniceoffei-memorial/`, kept for reference; delete it once you're happy).

| Page | Path | Notes |
|---|---|---|
| Home | `/` | Hero portrait, memorial book, featured "Life Is Short" video, ForeverMissed, donations |
| Her Music | `/music` | Featured video, albums and singles, listening panel (Spotify / YouTube) |
| The Memorial Book | `/memorial-book` | Self-hosted page-turning reader, PDF download |
| Reader window | `/memorial-book/reader` | Full-window reader, no site chrome |
| Donate | `/donate` | Shareable page; same content as the Donate panel |
| Thank you / Payment failed | `/thank-you`, `/payment-failed` | Where the checkout redirects after a payment (noindex) |

`/?donate` opens the Donate panel on arrival and `/tributes` redirects to ForeverMissed, because
those links have already been shared.

## Setup

```bash
npm install
npm run dev     # http://localhost:3000
npm run build
npm run start
```

Environment variables (see `.env.example`; copy it to `.env.local` locally):

- `NEXT_PUBLIC_CHECKOUT_URL` (**required**): the donation checkout link, e.g. the UAT link
  locally and the live link in production. `next dev` and `next build` stop if it is missing.
  Its origin is also the only checkout host allowed in the CSP `frame-src`.
- `NEXT_PUBLIC_SITE_URL`: the live domain for canonical / social URLs.
- `NEXT_PUBLIC_DONATION_EMBED_HOSTS`: hosts where "Give online" opens inside the Donate panel.
  The provider only allows framing on `www.berniceoffei.com`, so everywhere else (localhost,
  Vercel previews) it opens the checkout in a new tab.

## Updating content

| What | Where |
|---|---|
| Names, dates, ForeverMissed link, embed hosts | `src/content/site.json` |
| Mobile Money number, short code, bank details, donation wording | `src/content/donations.json` |
| Albums, singles, featured song, Spotify/YouTube links | `src/content/discography.json` |
| Release artwork | `src/assets/artwork/` + the map in `src/content/artwork.ts` |
| Photographs (portrait, book cover, Life Is Short artwork) | `src/assets/photos/` |
| Memorial book page images, PDF and page count | generated by `npm run book` |

**Music.** Each release in `discography.json` has `title`, `type` (`album`/`single`), `year`
(a confirmed year only, otherwise `null`; the card then shows "Album"/"Single"), `artwork`,
`spotifyId` + `spotifyUrl` and `youtubePlaylistUrl`. Order in the file is display order. To add a
release, add an entry, drop its cover into `src/assets/artwork/` (or set `artworkSource` and run
`npm run artwork`), and add the import to `src/content/artwork.ts`.

**Memorial book.** `npm run book -- "/path/to/Final Brochure.pdf"` regenerates
`public/book/pages/`, `src/content/book.json` and
`public/downloads/bernice-ofeibea-offei-memorial-book.pdf`. Then update `PDF_SIZE` in
`src/lib/book.ts` to the size it prints.

## How it works

- `src/app/layout.tsx`: fonts (self-hosted via `next/font`), metadata, global CSS.
  `(site)/layout.tsx` adds the header, footer and Donate panel; `(reader)/` has none.
- `src/styles/`: `global.css`, `music.css` and `book.css` are the design's stylesheets, carried
  over unchanged apart from the font variables; `status.css` styles the 404 / thank-you /
  payment-failed pages.
- `src/components/`: `SiteHeader`, `SiteFooter`, `DonateDialog` + `DonationOptions`,
  `FeaturedRecording`, `ReleaseCard`, `ListeningPanel`, `BookReader`.
- `src/lib/media.ts`: a small event bus so only one player sounds at a time (featured video,
  listening panel, donation checkout). Players are created on click; nothing autoplays.
- `src/lib/flipbook.ts`: the reader. The page-turn effect is
  [`page-flip`](https://github.com/Nodlik/StPageFlip) (MIT, no release since 2022). Navigation,
  zoom, fullscreen, sound, keyboard and `#page/12` deep links are ours. It returns a destroy
  function, so the reader is torn down cleanly on client-side navigation.

**Things that are easy to break**

- **The CSP `frame-src` in `next.config.ts`.** It allows only the checkout, YouTube (no-cookie)
  and Spotify, and deliberately not this site. After a payment the checkout sends its frame to
  `/thank-you` or `/payment-failed`; the browser blocks that, and `DonateDialog` sends the whole
  tab there instead. The inline script in `layout.tsx` is a second safety net for the same case.
- **page-flip workarounds** in `book.css` (wrapper padding override, so it doesn't cover the
  toolbar) and `flipbook.ts` (closed covers centred by translating `.stf__block`; the library's
  never-ending animation loop is silenced on destroy).
